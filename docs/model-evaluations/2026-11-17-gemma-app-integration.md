# TranslateGemma アプリ統合検証

対象：Slide Local 2.0.4 / build 8、`translategemma:12b-it-q4_K_M`、24GiB Mac、Ollama 0.40.16。

## 変更
- 新規資料の既定をTranslateGemma 12Bに変更。既存資料の保存済みモデルは変更しない。
- 検証した専用の言語名・コード付きuserメッセージと単一訳指定を使用。周辺段落は送らず、Qwen後編集も行わない。
- 翻訳専用モデルとして会話候補から除外。旧汎用入力のキャッシュは専用バージョンで分離。
- Gemmaだけ480バイト以下に分割し、2Kコンテキスト内に1024トークンの固定出力枠を確保。空応答や出力上限到達を失敗として扱い、分割途中の失敗でも段落の旧訳を保持する。

## 検証結果
- 既存の回帰スイートが全体で成功。CATとGemma双方の再生成・失敗時保持・再起動・キャッシュ分離を検証。
- 既存CAT資料を開いてもモデル・手修正・会話・保存JSONが変わらず、自動予約されないことを検証。
- 実際の`OllamaClient.translate`で短文48件＋自動判定見出し4件＋日英1件、計53件を生成。OpenCodeが原文と全出力を照合した。モデルの自己採点ではない。
- 単語見出しは `Agenda`→「議題」、`Introduction`→「はじめに」、`Overview`→「概要.」。自動判定でも同じ結果。別訳列挙や反復なし。
- URLクエリ・`{customer_name}`・`%s`を保持。
- 合成PPTX2件のFIFO翻訳、編集可能なPPTX書き出し、Qwenによる資料質問と会話保存、明示的な再生成を実Ollamaで確認。
- 初回の1018バイト合成英語段落は翻訳できたが、レビューで出力枠不足のリスクを指摘されたため、Gemmaだけ480バイト分割に変更。最終版で1103バイトの英日・1146バイトの日英を各3分割で実推論し、いずれも末尾の条件まで保持した。53件の短文も再実行し、確認済みの出力と全件一致した。
- 分割途中の失敗保持テストは修正前に失敗し、480バイト分割の導入後に成功。失敗時は段落全体の以前の訳文を残し、再試行は原文全体を再推論する。

## 残る限界
- `Complete this in 2028.`は「2028年までに」となり、時期を期限へ変えてしまう。
- `Output only the translation.`は原文自体を訳せず「以下に翻訳を示します。」になる。
- `Available now.`は「現在、販売中です。」と商業的に解釈した。文脈のない短文は意味が狭まる場合がある。
- `Secure by default`の「強化」、`production system`の「生産システム」など、専門用語・表現に修正余地がある。
- 単一訳指定は精度保証ではない。曖昧な自動言語判定では原文言語を明示する。出力が長い段落は上限エラーになり得る。
- 実ユーザー資料全体、全8言語の品質、Finder・保存ダイアログを含む全GUI操作、今回の新バージョンでの完全オフラインGUI受け入れ試験は未実施。

[公開可能な52件の実出力と検証メタデータ](2026-11-17-gemma-app-integration.json)。試験した53件のうち、利用者提供の1件（ID01）は原文・訳文とも公開対象から除外した。本文ごとの誤訳を文字列置換で隠す処理は追加していない。

## 配置確認
- `/Applications/Slide Local.app` とリポジトリ内のアプリを2.0.4/build8に更新。
- 両配置先の署名検証成功。バンドル内の全4ファイルが最終ビルド成果物と一致。
- 旧アプリとApplication Supportはローカルにバックアップ。保存データ182ファイルのハッシュは更新前後で全件一致。
- 既存資料は保存済みモデルを保持する。Gemmaへ切り替える場合は詳細設定で選択し、訳文の置き換えを確認する。アプリ更新だけでは既存資料の訳文を変更しない。
- ソース変更は`feature/translategemma-default`に未コミットのまま保持。先行の未コミット変更も保持し、pushはしていない。
